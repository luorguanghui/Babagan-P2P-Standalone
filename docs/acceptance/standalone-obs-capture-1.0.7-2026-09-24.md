# 独立客户端 1.0.7：OBS 虚拟摄像头采集

## 目标与改动

Windows 共享来源新增“OBS 虚拟摄像头”，与原屏幕/窗口采集并列。客户端按精确设备 ID 打开名称为 `OBS Virtual Camera` 的视频输入，并沿用现有共享锁、WebRTC P2P/TURN 连接及 H.264 硬件编码。OBS 模式只传视频；麦克风维持现有路径，系统声音勾选项禁用。共享结束或轨道停止时释放设备和防休眠锁。快速停止后再次共享不会被前一次的超时计时器误停。

## 验证

- 本机 OBS 32.1.2 已启动虚拟摄像头；Electron 能枚举 `OBS Virtual Camera`，获取活动视频轨道，设置为 2560×1440 / 60 fps。轨道在约 3 秒观察期报告约 175 个呈现帧。
- 真实 OBS → Windows Electron → Chrome 观看端：前台采集约 60.0 fps、发送约 60.0 fps；最小化后采集约 59.9 fps、发送约 59.9 fps、观看端解码约 59.7 fps。发送端使用 `MediaFoundationVideoEncodeAccelerator (NVIDIA H.264 Encoder MFT)`。
- 此次自动画质测试的发送分辨率为 960×540，说明保持 60 fps 时仍可能受 WebRTC 带宽控制影响而降清晰度。固定 1080p 上限的补充测试也因浏览器带宽估计降到 960×540；不能据此承诺 1080p60 恒定输出。
- 单元测试覆盖只选择 OBS 设备、精确设备 ID、帧率约束与错误提示；Electron 测试覆盖本地视频输入权限；在线双端测试覆盖屏幕共享后切换 OBS、视频到达、停止、重连与会议结束。审查还发现双击共享或离会时取流尚未完成会泄漏迟到的视频轨道；新增线上回归测试先复现两次取流，再验证新逻辑只启动一次，离会后迟到轨道被停止。

OBS 虚拟摄像头仅替代采集。会议软件仍执行 WebRTC 视频编码；若要让 OBS 同时编码，需另建 WHIP 接入及多人分发链路。
