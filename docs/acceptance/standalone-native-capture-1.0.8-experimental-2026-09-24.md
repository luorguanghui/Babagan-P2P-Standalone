## 已核验

- 71 个独立客户端单元测试通过，改动目标文件的 ESLint 通过。
- Windows 解包目录含独立 libobs 运行库、采集助手和 GPLv2 文本。直接运行解包目录中的助手，5 秒采到 299 帧，9 个抽样均有非黑画面。
- 本机 Electron → 内置采集助手 → WebRTC 回环：音频和视频两轨连接、约 60 fps 视频编码/解码，系统音频轨收到数据。
- 最小化 10 分钟原型试验：60 个 10 秒窗口的编码中位数 60.1 fps，最低 49.4 fps；因此严格的“每个窗口 ≥50 fps”门槛未通过，内置模式保留“实验”标识。

## 待用户实测

1. Windows 选择“内置高帧率屏幕采集（实验）”，设置 60 fps 并最小化；手机观察实际到达/解码帧率与画面内容。
2. 勾选“系统声音”后，用可辨识音画测试素材检查手机端同步与回声。
3. 增加至三到四名接收者，观察各连接码率上限、总上行和画质是否公平；可手动设置视频总上行上限。
4. 切换 Windows 显示分辨率、断开/恢复显示器及音频设备，检查能否恢复。

此 Windows 内置模式当前只提供整个屏幕；单窗口继续用原有“屏幕 / 窗口”来源。未完成真实 Android 设备的音画偏差、显示模式切换和相对 OBS 的延迟验收。对外分发含 libobs 的安装包前仍需处理对应源码及第三方依赖许可证要求。
