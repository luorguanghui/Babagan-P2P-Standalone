# 独立客户端 1.0.5：前后台共享帧率

## 现场复现

- 用户正在进行的 Windows 1.0.4 会议中，1080p / 60 fps、固定画质上限、P2P 直连，前台发送统计为 56.3–57.0 fps；最小化约 10 秒后为 32.8 fps。安卓截图显示同一共享者 1925×1083、解码 22.7 fps、下行约 3.96 Mbps。
- 手机总览的“目标 30 fps”来自手机本地默认发送预设。安卓端不能发起屏幕共享，该预设没有作用于接收视频。
- 本机另一轮独立屏幕共享测试中，保持低复杂度运动画面时，最小化后发送仍为 56.3 fps。高复杂度画面时约 32 fps。因此没有证据表明程序在所有后台状态统一锁到 30 fps；内容复杂度与采集、编码和接收解码应分别测量。

## 修复

- 发送统计新增屏幕采集 fps。采集接近 60 fps、编码连续约 6 秒低于目标 75% 时，固定画质上限模式也会逐步降低实际发送分辨率以保帧率；稳定后缓慢恢复。采集本身帧率低时不进行无效降分辨率。
- 安卓总览不再显示本地“目标 30 fps”，接收统计分别显示到达与解码帧率和视频编解码格式，便于区分传输与解码瓶颈。
- 修复客户端 WebSocket 心跳中未初始化的 `lastPong` 变量，并让 Android 构建脚本在当前 PowerShell 环境中正确输出 SHA-256。

## 验证

- 客户端 Node 测试 35 项通过，新增采集/编码帧率区分、固定模式降分辨率、静态画面不降画质和发送参数回归测试。所改客户端及测试文件 ESLint 通过。
- 在线 Cloudflare 双端媒体冒烟测试通过，包含共享、音频、停止、重连和移动端布局。
- Windows 1.0.5 打包通过；解包后的可执行文件完成在线入会、原生选择器、麦克风和结束会议冒烟测试。
- Android 1.0.5 `versionCode=6` 打包通过，APK v2/v3 签名验证通过；包内资源已核对。没有在用户手机上安装或对新包进行真实设备帧率复测。
- 当前目录中 1.0.4 APK 的签名证书 SHA-256 为 `7b84351eb4df219a3630d89c594787862dcf9683cc44646bf6f9864cecd829ef`，1.0.5 为 `a1599a0e3f0bccdbfcf203738e23648b3e443bdab0c09b223aee12e292191f8b`。旧签名私钥不在本机可找到的位置，Android 无法覆盖升级；需会后卸载旧版后安装新版，或取得旧私钥重新签署。

若新版本的“采集”在后台也降至约 30 fps，降低编码分辨率无法凭空补出未采集的帧；应结合该数值继续诊断 Windows 屏幕采集或被共享内容的刷新行为。若“采集”接近 60 fps 而“发送”下降，新版回退逻辑会优先保持发送帧率，代价是必要时降低分辨率。
