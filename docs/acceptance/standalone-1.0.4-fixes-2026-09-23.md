# 独立客户端 1.0.4 问题修复与验证

2026-09-23 针对 EXE / APK 实测反馈的连接路径不一致、动态共享码率卡在约 1 Mbps，以及复制邀请提示不消失进行修复。

## 诊断与改动

- WebRTC stats 在 ICE 重选后可能同时保留多个成功候选对。原代码会按遍历顺序取最后一个 nominated 或 selected 候选对；若旧直连候选对排在实际选中的 TURN 候选对之后，就会误报 P2P。现在优先读取视频 transport 的 selectedCandidatePairId，其次使用唯一的 selected 候选对；数据不明确时显示“路径待确认”。带宽估计与路径标记共用这一选择规则。
- 用户截图显示动态共享约 29.3 fps，带宽估计 1.30 Mbps，但客户端码率上限已降到 0.50 Mbps。旧算法在 `qualityLimitationReason=bandwidth` 时每轮继续退让，即使浏览器估计值已高于客户端上限；丢包或 RTT 统计缺失时又不能恢复。现在仍在高丢包、高 RTT 或估计带宽不足时降码率；动态画面且估计值高于当前上限时，逐步恢复发送上限。
- 复制邀请的成功提示现在 2.5 秒后清除；复制失败时的手动复制提示 5 秒后清除。后续错误提示不会被旧的定时器清除。

## 验证

- 独立客户端 Node 单测：27 项通过；回归覆盖旧 nominated 候选对、候选对不明确、截图中的低码率恢复和提示定时清除。
- 仓库 Vitest：44 个文件、769 项通过。改动的客户端与测试文件通过 ESLint。全量 `eslint apps/standalone/client` 仍在未改动的 `audio-processor.mjs` 有 2 项旧错误。
- 在线 Cloudflare Worker 入会、WebSocket 信令、授权和短期 TURN 凭据验证通过。
- 双 Chromium 在线媒体测试通过：自动模式与“一端强制 TURN”混合模式下两端连接标记一致；混合模式两端均显示 Cloudflare TURN。共享画面、停止、重连、语音和复制提示自动消失均通过。
- 1.0.4 Windows 打包成功；解包后的 Electron 可执行文件完成线上入会、选择器、麦克风与结束会议测试。便携 EXE 的 Playwright 直接附加在 30 秒内超时，因此该项未作为运行验证依据。
- 1.0.4 Android APK 构建成功，versionCode 5，APK v2/v3 签名验证通过；已确认新客户端资源包含在 APK 中。未进行 Android 真机复测。

这不是跨运营商带宽或真实设备性能验收。实际发送码率仍由 WebRTC 拥塞控制、接收反馈和源画面复杂度决定；若浏览器估计带宽长期维持约 1.3 Mbps，不能保证实际上传显著高于 1 Mbps。截图中的实际发送分辨率 722×406 接近源分辨率，选择 1080p 目标不会创造额外像素。

安装包和 SHA256 校验文件位于 `output/standalone/`。
